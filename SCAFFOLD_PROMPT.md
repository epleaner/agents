# Scaffold Prompt for New Repositories

Give this prompt to an agent in a new repository to set up the Codex multi-agent workflow:

---

## Prompt:

```
Please scaffold this repository with the Codex multi-agent workflow system using the local yepe tool.

**Step 1: Run yepe from the local agents repo**

From /Users/ep/workspace/agents/packages/yepe, build and link yepe:

```bash
cd /Users/ep/workspace/agents/packages/yepe
npm run build
npm link
```

**Step 2: Run yepe in this repository**

Make sure this repository has git initialized and a clean working tree, then run:

```bash
yepe
```

You'll be prompted for project information (required fields marked with *):

**Required:**
- * Project name
- * Purpose/goals (1-2 sentences)
- * Beads prefix (2-4 characters for issue IDs)

**Optional (press Enter to skip):**
- Tech stack (comma-separated, e.g., "TypeScript, React, Node.js")
- Code style (e.g., "Prettier, ESLint, 2-space indent")
- Architecture patterns (e.g., "Clean Architecture, DDD")
- Testing strategy (e.g., "Jest unit tests, 80% coverage")
- Git workflow (e.g., "trunk-based", "GitFlow")
- Domain context (what should AI know about your business domain?)
- Important constraints (technical, business, regulatory)
- Key external dependencies (APIs, services)
- **Skill selection** (choose which external integration skills to include)
  - Options: slack-notify, jira-lookup, jira-update, linear-sync, fathom-notes, action-items, knowledge-graph, cloud-deploy
  - You can select individual skills (e.g., "1,3,5"), all ("a"), or none ("0")

**Error handling:**
- If you miss a required field, you'll be re-prompted (no exit/restart needed)
- Invalid beads prefix length will re-prompt

yepe will:
1. Copy all workflow files (AGENTS.md, .opencode/, openspec/, learnings/, bin/)
2. **Only copy selected skills** from .opencode/skill/
3. Copy **template-only learnings files** (no actual entries from blueprint repo)
4. Customize openspec/project.md with your project details
5. Customize AGENTS.md header with your project name and context
6. Generate a report in .yepe-report.json

**Step 3: Review the changes**

```bash
git status                  # See what was added
cat .yepe-report.json      # Review the detailed report
cat openspec/project.md    # Check customized project info
head -50 AGENTS.md         # Check customized header
ls .opencode/skill/        # See which skills were installed
cat learnings/index.md     # Check that learnings are template-only
```

**Step 4: Initialize beads**

```bash
bd init <prefix-you-chose>
bd doctor                  # Verify setup
```

**Step 5: Commit the scaffold**

```bash
git add .
git commit -m "Add Codex multi-agent workflow scaffold

- Added AGENTS.md with project-specific context
- Added .opencode/ agent definitions
- Added openspec/ change proposal framework
- Added learnings/ meta-learnings ledgers
- Added bin/ helper scripts
- Initialized beads issue tracking"
```

**Step 6: Create your first issue**

```bash
bd create --title="Complete workflow onboarding and customization" --type=task --priority=2
bd ready               # Verify it shows up
```

**Step 7: Push to remote (if configured)**

```bash
git push
bd sync                # Sync beads with remote
```

You're now ready to use the full Codex workflow with beads, OpenSpec, and multi-agent collaboration!
```

---

## Alternative: Non-Interactive Setup

If you prefer to set default values without prompts, you can create a `.yeperc` file in the repository:

```json
{
  "name": "My Project",
  "purpose": "A web application for...",
  "techStack": ["TypeScript", "React", "Node.js"],
  "beadsPrefix": "myapp"
}
```

Then run `yepe --silent` to skip prompts and use the config file.

_(Note: This feature is not yet implemented but can be added if needed)_

## What Gets Installed

After running yepe, your repository will have:

### Core Files
- **AGENTS.md** - Main agent instructions, customized with your project info
- **.opencode/** - Agent definitions, commands, skills, templates
- **openspec/** - Change proposal framework with customized project.md
- **learnings/** - Meta-learnings ledgers and index
- **bin/** - Helper scripts (review-learnings, etc.)

### Configuration
- **.yepe-report.json** - Detailed report of what was copied and any conflicts
- **openspec/project.md** - Your tech stack, conventions, domain context
- **AGENTS.md header** - Project name, purpose, constraints in agent instructions

### Generated by Next Steps
- **.beads/** - Created by `bd init` (issue tracking database)
- **.openspec/** - Created by `openspec init` if needed (proposal metadata)

## Troubleshooting

**"Not a git repository"**
```bash
git init
git add README.md  # or any file
git commit -m "Initial commit"
```

**"Working tree is not clean"**
```bash
git status
git add .
git commit -m "WIP"
# or
git stash
```

**Conflicts detected**
- Check `.yepe-report.json` for conflicting files
- Manually merge any conflicts
- Re-run `yepe` to update (it's idempotent)

**Want to update after initial scaffold**
- Just run `yepe` again
- It will only add new files, won't overwrite existing ones
- Check the report for any new additions
