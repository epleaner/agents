# Recurring Tasks Ledger

Track manual or repetitive tasks that could become commands, scripts, or skills. Only capture operational/process knowledge—domain facts should remain in the knowledge graph.

## Entry Template
```
### [ENTRY_ID] <concise title>
- Date: YYYY-MM-DD
- Session: <session identifier or transcript link>
- Knowledge Type: meta
- Meta Category: recurring-task
- Owner: <agent responsible for investigating automation>
- Status: new|needs-agents-update|needs-spec-change|in-progress|promoted|closed
- Related IDs: beads-xxx, change-yyy (comma-separated or `none`)
- Summary: <1–3 sentences describing the recurring task>
- Recommended Action: <automation idea or policy update>
- Supporting Links: <transcripts, AGENTS diffs, etc.>
- Follow-up Links: <AGENTS/spec updates, beads issues, etc.>
```

**IDs:** Use `RT-YYYYMMDD-###`. Reference each entry inside `learnings/index.md` for quick discovery.
